# 旅人登记与世界系统：实现落地文档

日期：2026-11-01  
状态：产品与工程实施依据  
相关文档：[世界系统改进书](WORLD_SYSTEM_REDESIGN.md)、[下一阶段优化方案](NEXT_STAGE_PLAN.md)

## 最新修订：统一角色属性

根据实际试玩反馈，角色页只展示力量、耐力、学识、技巧、韧性一套当前属性，不再同时展示“初始画像”和“属性回响”两套同名数值。以下规则取代本文中关于分区展示、初始倾向不计入角色属性的旧约定：

- 当前属性 = 登记基础值 + 当前有效旅志累计成长。例如基础力量 4、旅志成长 2，角色页只显示“力量 6”。
- 登记基础值仍由本地确定性问卷生成，范围 1–5；跳过或旧用户默认每项 3。角色当前属性没有 5 点上限。
- 主界面不展示第二套数值、五格量表或分母；点击属性后才展示基础值、累计成长、当前值，以及原有来源旅志。
- 登记结果页预览确认后的当前属性，重答时包含已有旅志成长，并明确说明基础值会更新、成长会保留。
- 存储和结算继续保留基础值与成长账本的独立来源。统一展示通过投影相加完成，不把问卷分数写入成长账本，不改变每日上限、AI 规则、营地进度或证据追溯。
- 重新登记是替换基础值，不是叠加一次奖励；旅志编辑、删除或重新结算后，角色页根据当前有效账本自动更新。

验收：新用户确认登记前后的属性一致；同项基础 4 加旅志成长 2 显示 6；跳过用户显示每项 3；重答和取消重答均不修改成长账本；角色页始终只有一套属性列表。

## 1. 目标与整体体验

新用户首次进入时，用一小段像素风开场和纯选择题建立角色与现实用户的初步联系。问卷根据玩家的近期行为估算力量、耐力、学识、技巧、韧性五项“初始倾向”，在角色档案中展示。进入营地后，角色会在更大的像素场景中活动；篝火是查看营地阶段、下一次变化和旅志来源的入口。之后的旅志仍按已有固定规则产生可追溯的成长，并推动营地发生可见变化。

完整体验顺序：

> 旅人来到营地 → 选择题形成初始画像 → 角色进入世界 → 记录真实生活 → 角色属性成长、营地回应 → 从篝火查看变化及其旅志来源 → 看见下一项营地目标。

这是一份轻量、可修改的自我画像，不是人格、能力或心理测评。问卷结果不决定玩家价值，不给出好坏评价，也不替代之后真实生活形成的成长。

## 2. 设计约束

- 全部题目为单选，不需要输入文字；建议 6 题，目标完成时间 30–60 秒。
- 询问近期具体情境和行为，避免“你是不是自律/坚强”等自我评判题。
- 每题 3–4 个同等合理的选项，并提供“最近没遇到 / 不确定”；整份问卷可以跳过。
- 不显示选项对应哪项属性，不出现“选择此项获得力量”的提示。
- 五项结果使用 1–5 的整数并标为“初始倾向”，结果页说明来自本次选择、可以重新回答。
- 初始倾向与旅志成长分开存储、分开呈现。初始画像不能增加/减少成长账本点数，不能触发营地里程碑，也不计作有效记录日。
- 画像可以影响角色的初始叙事、档案描述或轻量外观表现；不得改变回响规则、每日上限、属性成长效率或营地解锁条件。
- 选择答案、画像和更新时间只保存在本机，不上传服务端，不传给 AI。

## 3. 首次开场流程

### 3.1 序章：篝火边的登记

首次启动且尚无画像时，在主导航前展示独立的全屏序章。沿用现有像素场景和配色，不复制《辐射》的 UI、题目、图标或文案。

画面：角色来到尚未点燃的营地，篝火旁放着空白旅人档案。文案：

> “篝火还不认识你。先不问你想成为谁，只记下你最近是怎样生活的。”

主操作“开始登记”；次操作“稍后再说”。不要求账号、通知或任何其他权限。

### 3.2 情境单选

每屏只呈现一道题、一个简短进度提示和可点击选项。点击选项后进入下一题，可返回上一题修改。点击“最近没遇到 / 不确定”同样进入下一题，不要求回答理由。中途退出后保存当前答案和题目位置；下次继续，不丢失进度。

题目主题应覆盖五项初始倾向且彼此交叉，最终文案在可用性试玩后冻结为 `questionnaireVersion = 1`。建议主题：

| 题目主题 | 关注的现实行为 | 覆盖属性 |
| --- | --- | --- |
| 最近有空闲时间时通常会做什么 | 身体活动、探索、制作、继续手头事项或恢复精力 | 力量、耐力、学识、技巧、韧性 |
| 最近一次接触陌生内容时怎么开始 | 查资料、请教、先尝试、拆成小步骤或暂缓 | 学识、技巧、韧性 |
| 一件需要持续投入的事情通常如何推进 | 分段完成、固定时间练习、边做边改或先完成关键部分 | 耐力、技巧、韧性 |
| 计划临时被打断时通常怎么调整 | 重排顺序、缩小目标、寻求帮助或留出恢复时间 | 耐力、韧性、学识 |
| 最近最有充实感的经历更接近哪类 | 身体挑战、持续完成、学到新东西、做出作品、应对变化 | 五项属性 |
| 遇到暂时做不好的事情时通常先做什么 | 重试、换方法、找示例、请人帮忙或休息后再来 | 力量、耐力、学识、技巧、韧性 |

选项描述具体、平行、无道德高低。不得把休息、求助、改计划写成低分或失败。题目只是一种低成本开局画像，不能宣称通过六题准确测得现实能力。

### 3.3 画像揭晓

篝火点亮，角色档案显示五项初始倾向。结果页同时说明：

> “这是根据刚才的选择整理出的此刻画像，不是定论。之后的旅程会继续改变你的角色。”

结果操作：

- “进入营地”：确认并完成首次登记。
- “重新回答”：回到题目，修改选择后重新计算。
- 已跳过的用户之后可从角色页选择“建立旅人画像”。

画像可附一条中性解释，解释来源于回答类别，例如“你最近更常选择动手尝试”。不得生成诊断式人格称号或负面标签。重复查看结果不重播首次完整揭晓动画。

## 4. 属性计分约定

### 4.1 问卷分数

- 计分表属于本地确定性 domain 逻辑，不调用 AI。
- 每个选项在计分配置中对一个或多个属性提供 0–4 的倾向分；界面不展示该映射。
- 每项属性至少由两道题观察。对某属性无关的题不计入该属性的平均；“不确定 / 最近没遇到”对本题涉及属性使用中点 2。
- 先计算每项属性在适用题目中的平均分 `average(0..4)`，再用 `1 + round(average)` 转成 1–5 初始倾向。四舍五入规则固定并有单元测试。
- 若整份问卷跳过，使用五项均为 3 的中性默认画像，标记为 `SKIPPED`；该默认值只用于完成角色档案，不产生任何成长点。
- 问卷题目或计分表变化时递增问卷版本。旧版本已保存画像不因升级静默重算；用户主动重答后使用当前版本并记录更新时间。

### 4.2 与角色成长的关系

现有 `GrowthRules`、`GrowthLedger` 和 `observeAttributeTotals()` 保持只代表旅志产生的成长。本次不得把问卷分数混进 `attributeTotals`，避免旧旅志回溯、每日封顶、证据来源或属性详情因此改变。

角色页分区显示：

- **初始画像**：五项 1–5 倾向，可查看或重新回答。
- **旅程成长**：当前账本累计点数及来源旅志，保持现有显示和追溯行为。

如果未来决定将初始值并入某种战斗或等级系统，必须另立数值方案，明确基础值和成长值来源，并重新验证不同起始画像的公平性；不属于本次实现。

## 5. 数据结构与迁移

使用现有 Room 数据库本地保存画像，不新增网络或账号依赖。

建议新增：

- `TravelerProfileEntity`：单例 ID、问卷版本、状态（`COMPLETED` / `SKIPPED` / `LEGACY_NEUTRAL`）、五项初始倾向值、创建时间、更新时间。
- `TravelerAnswerEntity`：问题 ID、选项 ID、问卷版本；以问题 ID 为主键。重答时在同一事务中替换答案和画像。
- 领域模型 `TravelerProfile`、计分器 `TravelerProfileScorer`，视图状态包含当前题目、答案、画像和保存/完成状态。

数据库从 v2 升至 v3：

- 为已有安装创建一个 `LEGACY_NEUTRAL` 画像，五项均为 3，避免升级后老用户被强制带入首次问卷。
- 新安装的空数据库不预先写入画像；无画像时显示开场登记。
- v1 数据库先按已有 1→2 迁移，再执行 2→3。
- 迁移不得修改旅志、回顾、证据或成长账本。Room 导出 schema，并增加 v2→v3 和完整旧版本迁移测试。

如果用户跳过，持久化中性画像和 `SKIPPED` 状态，直接进入应用；之后可从角色页建立画像。这样不需要在每次启动都弹窗。

## 6. 工程边界

- `domain`：问题/选项定义、稳定 ID、计分权重和纯函数计分器；不依赖 Compose、Room 或 Android UI。
- `data/local`：画像与答案 Entity、DAO、v2→v3 Migration。
- `LifeTimeRepository`：观察/保存/跳过/重答画像的事务 API；画像变化不触碰成长账本和营地结算。
- `LifeTimeViewModel`：暴露开场状态、当前题号、答案选择、前进/返回、继续登记、完成、跳过与重答操作。
- `LifeTimeApp`：仅新安装的首次空数据库进入登记路由；登记完成或跳过后进入既有四页导航。重启或进程被系统回收时恢复进度。
- `ui/screens`：新增登记序章、单题选择和画像揭晓界面；沿用现有像素组件、字体和边距规范。
- `CharacterScreen`：增加初始画像分区，继续使用原有成长总值和来源数据展示旅程成长。

可选问题 ID、选项 ID 和问卷版本必须稳定，不能以界面文案作为数据库主键。

## 7. 画像子系统实施细节

### 画像 A：冻结体验和计分定义

- 完成六道题的最终中性文案、所有单选项和中点选项。
- 给每项属性定义至少两道题的计分覆盖，编写计分表和边界例子。
- 用 3–5 名目标玩家走查，确认操作无需解释、选项没有明显正确答案，单次用时不超过一分钟。

### 画像 B：实现领域和存储

- 实现可测试的问卷计分器和 ID/version 常量。
- 增加 Room v3 Entity、DAO、Repository 事务和迁移。
- 完成从无答案、部分回答、跳过、完成、重答的读写流程。

### 画像 C：接入首次导航和界面

- 新用户首次进入走“序章 → 单选题 → 揭晓 → 世界页”，让玩家先看到角色和营地；可从主导航直接进入今日页记录。
- 支持上一题、暂时退出、恢复进度、跳过、重答。
- 老用户升级后正常进入原页面；从角色页可选建立画像。
- 角色页分别呈现初始画像和旅程成长。

### 画像 D：验证试玩

- 生成新安装 APK 和升级覆盖 APK。
- 验证新安装首次流程、升级用户无强制弹窗、跳过后不重复弹出、部分答题重启恢复、重答只更新画像。
- 试玩观察答题耗时、是否理解“倾向不是定论”、结果是否让玩家感到被评判，以及是否增强对角色的认同。

## 8. 画像子系统验收细则

### 行为

- 首次启动展示序章；每题只能单选，所有题无需输入文字。
- 所有题完成后稳定生成五项 1–5 初始倾向；同一答案与版本得到完全相同结果。
- 点击“不确定 / 最近没遇到”可继续；跳过后显示中性画像并进入主界面。
- 中途退出并重启后能恢复到未完成的题目和已有选择。
- 重答后新画像覆盖旧画像，更新时间和问卷版本正确。
- 现有成长账本、角色成长总点数、证据详情和营地状态不因问卷完成、跳过或重答发生变化。
- v2 升级至 v3 不丢数据、不要求老用户完成问卷；v1 经连续迁移同样通过。

### 体验

- 至少 4/5 名试玩者能在无口头解释的情况下完成；中位用时不超过 60 秒。
- 玩家能复述“初始倾向是开局画像，之后旅志带来成长”。
- 选项没有明显道德高低；玩家不会因较低数值被描述成懒惰、脆弱或能力不足。
- 小屏、系统字体放大、TalkBack 单选语义和系统减少动画设置下仍可完成流程。

## 9. 本次不做

- 自由文本自我介绍或 AI 性格分析。
- 心理/健康诊断、人格类型、职业适配或对用户能力的断言。
- 问卷直接授予属性成长、营地进度、货币、连续记录奖励。
- 问卷结果上传、账号同步或用于广告画像。
- 大量题库、随机题、复杂可信度区间和问卷排行榜。

## 10. 世界系统改造

世界系统与首次画像共同构成开局体验，不只是附带链接。玩家完成登记后，必须能进入一个有角色、有活动、有明确交互和下一步目标的营地。

### 10.1 世界页主场景

- 世界页首屏以像素营地为主，目标占可用内容高度一半以上；减少当前场景下面重复解释等级的文字卡片。
- 保留篝火、帐篷、路标、工坊，以前景/中景/背景和营地边缘扩展画面纵深。第一轮先扩大并重排现有场景，不要求一次制作大地图。
- 角色在少量预设路径点间缓慢游荡，闲置时可坐到火边、查看路标或整理背包；营地苏醒后才会偶尔进入工坊。
- 角色动作使用有限像素帧和确定性状态切换，不使用物理模拟或网络动画。页面不可见时暂停动画；系统减少动态效果时显示完整静态帧。
- 动画角色和建筑的点击热区绑定场景坐标，不随角色移动错误偏移；各热点保持独立无障碍名称、足够大的触控区域和按压反馈。

### 10.2 篝火档案

篝火始终可点击，包括初始营地。点击后打开营地档案底部面板，展示：

- 营地阶段名称和醒目的像素徽记。
- 已发生的实际变化，例如“篝火点亮、路标修复”。
- 有效记录日数、下一里程碑目标和距离目标还差几天。
- 对当前营地变化有贡献的旅志日期列表；点击日期打开现有旅志详情。
- 最近一次世界变化的时间和来源。

初始状态下显示“营火尚未点亮”和“完成一次旅程回顾后点亮”，而不是禁用点击。路标打开冒险方向与旅程记录；工坊未开放时显示开启条件，开放后查看营地成长记忆。帐篷首版提供角色/近期旅程信息，不采集睡眠数据。

世界进度继续从有效回顾投影，不新增一份可与旅志冲突的等级存档。完成回顾的零成长日期也计入营地；待分析、失败、过期且未重新结算的旅志不计入。重复提交同一日期不重复推进。编辑、删除后按当前有效回顾重算，不惩罚断更。

### 10.3 首周可见里程碑

现有 1 天、3 天两个阶段间隔较长。建议累计 **1、2、3、5、7 个不同的有效回顾日期**出现世界变化，按累计次数而非连续签到计算：

| 有效回顾日期数 | 建议表现 | 角色回应 |
| --- | --- | --- |
| 1 | 篝火明显点燃，路标亮起第一道光 | 角色首次走到火边安营 |
| 2 | 修复一个营地细节或放入新物件 | 角色走近并查看新变化 |
| 3 | 工坊点亮 | 角色开始偶尔进入工坊 |
| 5 | 营地边缘路径延伸，出现新景观或记忆点 | 角色走向新路径 |
| 7 | 完成首周营地章节，出现七日记忆和下一阶段远景 | 展示由旅志组成的世界回顾 |

这些是推荐的体验节奏，具体资产可在原型试玩后调整。断更不熄灭营火、不扣等级、不锁回已有内容。首周后才评估每新增 7 个有效回顾日期开放一项较大的世界变化，避免增加每日催促。

由于营地阶段完全从回顾日期推导，首版不用为里程碑单独保存可变等级；实现时把当前 `CampState` 的阶段/下一目标投影扩展到里程碑表，属性账本仍保持原样。范围不包括自由摆放、资源链、订单、付费加速或社交家园。

### 10.4 首次结算回响

第一次有效回顾完成后，播放 3–5 秒、可跳过且不会阻塞操作的场景演出：

1. 轻微聚焦篝火。
2. 角色从帐篷附近走到火边。
3. 篝火燃起，路标产生短暂亮光。
4. 显示真实发生的变化及“再完成 1 个不同日期的回顾，营地会……”的下一目标。
5. “查看营地”进入世界页并打开篝火档案。

重复查看不重播整段。关闭动画或减少动态效果时仍展示静态的阶段变化。没有实际里程碑变化的后续回顾只显示真实回顾反馈，不制造虚假升级或离线收益。

### 10.5 画像与营地的连接

问卷结果可以决定角色档案中的一句中性初始描述，或选择轻量的初始站姿/背包小细节；不要让画像高低决定角色待遇、营地等级或获得资源。篝火点亮以后，角色行为由营地阶段决定，与属性画像分离。之后若要让长期旅志改变营地细节，来源必须仍能追溯到对应回顾。

## 11. 统一实施顺序

### P1：冻结体验定义

- 定稿 6 道单选题、选项和版本 1 计分配置。
- 定稿 1/2/3/5/7 个有效回顾日的场景变化草图和篝火档案内容。
- 以纸面/Compose 静态原型检查开场时长、角色首屏比例和篝火热区。

### P2：领域、存储与迁移

- 完成画像纯 Kotlin 计分逻辑、Room v3 迁移和答案恢复。
- 扩展世界进度投影，保证零成长有效回顾计入且修改/删除可回退。
- 覆盖画像和营地规则的单元测试、Room 迁移及 Repository 集成测试。

### P3：新用户开场与世界页

- 新安装流程为“序章 → 单选题 → 画像揭晓 → 世界页”；跳过进入原今日页。
- 做成放大的营地主场景、角色游荡状态机、篝火档案、路标/工坊点击入口。
- 角色页分开显示初始画像与旅志成长；既有四个主导航仍保留。

### P4：回响与里程碑

- 加入首次结算演出和第 2/3/5/7 个有效回顾日的场景反馈。
- 检查第一天的角色/营火变化是否醒目，第二个有效日期是否给出明确新目标。
- 完成新安装、升级覆盖、窄屏、减少动画、系统字体放大和 TalkBack 验收后生成试玩 APK。

### P5：试玩收敛

- 进行七日体验观察，不以连续签到作为成功指标。
- 记录答题耗时、首日变化发现率、篝火档案可理解度、第二个有效日期回访动机和角色动画干扰情况。
- 基于试玩决定是否调整里程碑内容、场景资产和画像叙事，不提前扩张装修/经济系统。

## 12. 合并验收清单

- 新用户可以在一分钟左右完成纯单选开场，也可以跳过；老用户升级不受阻。
- 初始画像与成长账本在 UI、存储和结算上互不混算；完成/跳过/重答均不改变既有旅志成长。
- 新用户画像揭晓后能看到角色进入营地，世界页首屏主角是大场景和游荡角色。
- 点击篝火可查看当前阶段、已发生变化、下一目标及来源旅志；点击来源可打开旅志原文。
- 第一次有效回顾有明显角色与篝火变化；第二个有效回顾有新的可见进展；后续里程碑依据有效日期累计且断更无惩罚。
- 零成长回顾计入世界；重复、失败、过期、编辑和删除行为与当前成长/回顾规则一致。
- 场景动画关闭时仍完整可读可交互；点击热区、导航和来源弹层可用。
- v1/v2 数据库升级后无数据丢失；旧用户不被强制进入登记。

完成 P1–P5 后，再决定是否让画像进一步影响角色外观或营地叙事。世界细节与市场参考的设计背景见[世界系统改进书](WORLD_SYSTEM_REDESIGN.md)。
