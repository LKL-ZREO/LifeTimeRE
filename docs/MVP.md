# MVP 开发约定

## 产品循环

玩家记录生活 → AI 自动回顾和识别行动 → 固定规则结算 → 角色属性与世界状态变化。
玩家无需分配点数或逐条批准 AI 判断。纠错是可选入口。

## 阶段一：工程与界面骨架

- Kotlin、Compose、Material 3、Navigation、ViewModel。
- Android 8.0 及以上，编译与目标 API 35。
- 今日、角色、世界、回顾四页。
- 深色主题、五项属性初始状态、营地示意场景。
- 草稿属于界面状态，不冒充已持久化的记录。
- 构建验收：assembleDebug、lintDebug。
- 运行验收：启动、四页切换、草稿切换保留、键盘与屏幕边缘布局。

## 阶段二：本地记录

- Room 保存 DailyEntry，包含 ID、创建时间、本地日期、时区、正文、更新时间。
- 支持保存、编辑、删除和本地日期归档。
- 正式持久化后开放保存按钮。
- 验收：重启仍保留；编辑、删除生效；跨日期记录归档正确。

## 阶段三：本地完整循环

- 建立 ReviewService 接口与明确标注的本地模拟实现。
- AI 分类、固定结算规则和界面分离。
- 使用结构化来源记录与引用片段解释成长依据。
- 初始参数：单项每天上限 3 点，全部属性每天合计上限 8 点。
- 五项属性：力量、耐力、学识、技巧、韧性。
- 角色总数值由成长账本派生，避免只保存一个可变总分。
- 相同内容重复结算不重复奖励；同日修订替换该日旧贡献，不在旧贡献上累加。
- 修改或删除记录使对应回顾过期；重新结算时替换旧贡献。
- 删除记录时清理相应敏感派生内容；删除全部数据也删除成长和回顾。
- 不因休息或断更扣点。修正旧结算产生的数值变化需单独说明。
- 世界状态由确定的成长里程碑派生，首版只扩展营地主场景状态。
- 验收：上限、重复提交、并发提交、同日修订、删除后的状态一致性。

## 阶段四：真实 AI

- 经后端调用 AI，密钥不放入 APK。
- 调用前说明哪些文字会发送到服务端，第一次使用时取得明确同意。
- 使用稳定属性 ID；AI 仅提供行动类别、有限等级与依据，不直接决定最终点数。
- 校验属性、等级、来源 ID、原文片段和响应长度。
- Prompt 将记录视为数据，忽略记录中试图修改系统规则的指令。
- 请求携带记录版本与幂等标识；拒绝覆盖已更新记录的过期响应。
- 网络失败保留原始记录，可重试，不虚报已成功结算。
- AI 无法判断时允许无成长结果；不将其解释为玩家失败。
- 验收：非法输出、缺少依据、提示词注入、超时重试、过期响应、重复结算。

## 暂不纳入

账户与云同步、定位与健康数据读取、战斗、装备、技能树、好友排行、复杂剧情。
当前版本优先验证记录与角色成长的核心体验。
