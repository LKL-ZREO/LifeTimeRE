# LifeTimeRE 下一阶段优化方案（初版）

日期：2026-11-01  
状态：开发依据；里程碑 A/B/C 已于 2026-11-01 完成。数值与文案在试玩后允许调整，但本文件列出的行为约束应保持一致。

## 1. 目标与范围

下一阶段交付一个可玩的纵向闭环：

> 记录真实的一天 → 自动生成有依据的回响 → 按固定规则增长属性 → 营地出现可见变化 → 点击变化，找回促成它的旅志。

这条链是与 Habitica 的任务勾选、金币和装备循环区分的核心体验。玩家可以选择现实中的冒险方向，但不选择属性类别或点数。第一版继续使用今日、角色、世界、回顾四个主页面；“回响揭示”作为保存后打开的临时视图，不增加第五个主导航项。

本阶段实施范围为下文的 A、B、C 三个里程碑。次日线索、周回顾和真实 AI 属于后续的 D、E；数据结构应容纳它们，但当前无需制作空入口。

## 2. 用户体验流程

1. 新用户首次进入可以完成可跳过的“旅人登记”单选序章，生成与旅志成长分开保存的初始画像；也可以跳过后直接写今日旅志。冒险方向同样可跳过，日后可在世界页设置或修改。登记流程的实施依据见 [旅人登记与初始画像](CHARACTER_ONBOARDING_IMPLEMENTATION.md)。
2. 点击“保存并生成回响”后，先将旅志保存在本机。界面明确显示“已保存，正在生成回响”。玩家可以离开页面，回来后继续查看状态。
3. 分析完成后展示“回响揭示”：先用一两句回顾当天，再列出识别出的行动及原文依据，最后展示属性变化和营地变化。玩家无需逐项批准。
4. 在角色页点击某项成长，可以回到对应日期和依据。在世界页点击新亮起的营地物件，可以看到促成该变化的有效日期列表，再打开对应旅志。
5. 当天修改旅志后，旧回响标记为过期并重新分析。新结果替换该日旧贡献；界面说明属性或营地为何发生修订。
6. 分析失败时，旅志仍保持已保存状态。玩家可以重试；在成功前不显示新属性点或世界解锁。

### 必须区分的状态

| 状态 | 玩家看到的含义 | 可进行的操作 |
| --- | --- | --- |
| 未保存草稿 | 文字只在编辑区 | 继续编辑、保存 |
| 已保存待分析 | 旅志已在本机，尚无新结算 | 查看记录、稍后返回 |
| 分析中 | 正在生成回响 | 离开页面；避免重复提交 |
| 已结算有成长 | 有证据支持的属性和世界变化 | 查看依据、查看世界 |
| 已结算无成长 | 当天仍有旅志，但没有足够证据加点 | 查看回顾、继续记录后重新分析 |
| 分析失败 | 旅志仍在，成长未更新 | 重试、编辑记录 |
| 回响已过期 | 原文已经修改，旧结果不再作为当前结算 | 等待重新分析或手动重试 |

“封存”容易让玩家误以为无法修改，正式保存按钮建议改为“保存并生成回响”。正在保存、无文字、内容未变化时，按钮分别给出明确状态。

## 3. 页面优化清单

| 页面 | 首批功能 | 验收时玩家应看见什么 |
| --- | --- | --- |
| 今日 | 读取当天旅志、编辑、保存、分析状态、回响揭示入口 | 保存后立即确认本地记录成功；分析失败不丢文字 |
| 角色 | 五属性实际数值、等级进度、最近成长、依据入口 | 数值变化与回响一致；点开可追溯日期和原文 |
| 世界 | 营地真实阶段、可点击物件、下一里程碑、冒险方向 | 第一次有效回响后至少一处画面明显变化；物件能指向来源 |
| 回顾 | 日期列表、详情、编辑、删除、结算状态 | 重启后仍能找回记录；删除后相关成长和世界状态同步变化 |

保留目前的像素美术语言。新的结算、编辑和确认界面沿用硬边面板、五属性颜色与中文可读字体；世界物件的点击区域必须有可访问的名称，不能只依赖像素坐标。

## 4. 成长与营地规则

### 属性结算

- 五属性保持力量、耐力、学识、技巧、韧性，使用稳定 ID；文字标签可调整，ID 不随文案变化。
- 识别服务只输出“行动类别、有限强度、对应原文片段、简短说明”。服务不能输出最终加点数。
- 结算器用版本化规则表计算增量。初始上限沿用现有约定：单属性每天最多 3 点、五属性合计每天最多 8 点。强度与具体增量的映射在 B 里程碑开始前冻结为测试用表。
- 同一行动不得仅凭重复措辞多次得分；同一天所有记录统一结算。没有充分证据时允许零成长，界面避免“失败”“懒惰”等评价。
- 休息或断更不扣点，不设置会损失已有收益的连续签到。修订或删除历史记录导致的数值回退，作为数据更正单独说明。
- 属性总值来自有效成长账本，不能只维护一个累加总数。等级进度也从已结算数据推导；具体经验曲线待第一轮数值试玩确定，不以硬编码占位数展示虚假进度。

### 营地的首批状态

当前场景已经画有帐篷、篝火、路标和工坊。首批美术改动直接在这张场景上做三态，不另建地图：

| 状态 | 条件 | 可见变化 | 可回溯来源 |
| --- | --- | --- | --- |
| 初始营地 | 尚无成功结算的日期 | 篝火较弱，路标和工坊保持昏暗 | 无 |
| 第一簇回响 | 至少 1 个不同日期成功结算 | 路标点亮、篝火更明亮 | 点击路标查看促成变化的旅志 |
| 营地苏醒 | 至少 3 个不同日期成功结算 | 工坊开灯、营地出现新的生活细节 | 点击工坊查看促成变化的日期列表 |

这里的“成功结算”包括有实际内容、完成回顾但零成长的日期：认真记录休息日也属于旅程。里程碑以不同日期计数，重复保存同一天不增加进度。已删除或过期且尚未重新结算的日期不计入当前营地状态；因此世界由当前有效记录推导，不保存一个无法校正的独立等级。今后可让玩家长期行动类别影响场景细节，但首批三态先保证清晰、稳定和可追溯。

## 5. 数据与职责边界

这部分定义业务对象和职责，不要求提前拆出大量模块。

| 对象 | 最少需要保存或提供的信息 | 约束 |
| --- | --- | --- |
| `DailyEntry` | ID、当地日期、时区 ID、正文、创建/修改时间、修订号 | 首版每天一条主旅志；历史日期不会因设备时区变化自动改写 |
| `Review` | 对应旅志 ID 和修订号、状态、回顾文本、识别结果、规则版本、时间 | 只允许当前修订号的结果成为有效回响 |
| `Evidence` | 稳定行动 ID、属性 ID、有限强度、原文引用或位置 | 引用必须来自对应旅志；不接受不存在的属性或来源 |
| `GrowthLedger` | 旅志 ID、修订号、属性 ID、实际增量、依据 ID | 相同来源只生效一次；修订时事务性替换旧贡献 |
| `JourneyDirection` | 可选目标文本或预设方向、更新时间 | 不直接参与点数计算；修改只影响之后的建议和叙事 |
| `CampState` | 当前阶段、可见物件及促成变化的旅志 ID 列表 | 由有效回响计算，不作为可独立修改的总进度 |

界面通过 ViewModel 读取统一状态；数据层负责本地保存；识别接口负责分类；结算器负责数值；世界投影负责营地状态。未来把本地模拟识别换成后端 AI 时，结算规则和四页 UI 不应随之重写。

## 6. 自动分析与可信度

在 A–C 里程碑，使用明确标注的本地演示识别器完成流程验证；界面显示“演示回响”，它只用于开发和试玩，不能在面向正式用户的版本中冒称真实 AI。演示识别器使用固定、可重复的示例或简单规则，不以它的分类准确率评价产品。演示内容应覆盖有成长、零成长、修订和失败四种情况。

E 里程碑接入真实 AI 时，必须先说明哪些文字会发送到服务端并取得明确同意。密钥留在后端。输出使用结构化格式；校验属性 ID、强度、来源 ID、引用片段与响应长度。旅志文本始终是待分析数据，不能凭其中的指令改变规则。请求携带旅志修订号和幂等标识；迟到的旧响应不能覆盖新记录。网络失败只影响回响生成，不影响本地旅志。

“这条判断不准确”作为回响详情中的纠错入口：玩家可以修改原文或标记某条依据有误并申请重新分析，但不能手动填写属性增量。首批至少要完成“修改原文 → 旧回响失效 → 新结算替换”；异议反馈的精细处理可在真实 AI 接入时补全。

## 7. 开发里程碑与验收

### A. 可留下旅程

引入本地持久化，完成每日旅志的保存、读取、编辑、删除和按日期展示；加入可跳过的冒险方向。今日页显示真实日期和保存状态。删除需确认，删除后清理关联的回顾、依据和成长。验收包括应用重启、屏幕旋转、跨日期、跨时区、空文字与超长文字。

实施状态：已完成本地保存、重启恢复、编辑、删除、修订号、当地日期/时区字段、历史时间线和冒险方向。当前已在 API 35 模拟器验证主流程；自动跨午夜刷新与多时区设备实测留作后续设备测试。

### B. 第一次成长

加入识别接口、本地演示识别器、固定结算器和成长账本；自动生成有依据的回响揭示。验收包括每日上限、重复提交、并发提交、零成长、同日修订、过期响应与失败重试。界面能清楚区分“旅志已保存”和“回响已完成”。

实施状态：已完成本地演示识别、版本 1 固定结算、回响与依据、Room 账本、角色真实属性、今日与回顾状态、失败重试及修订替换。已通过规则单元测试与 API 35 设备端数据库集成测试。演示识别器仅覆盖有限表达，不代表真实 AI 准确率。

### C. 营地回应

实现上述三态场景、从世界物件回到来源旅志、角色实际属性和可追溯详情。验收时，玩家第一次完成回响就能发现路标或篝火变化；达到第三个不同日期后能发现工坊变化；修改或删除来源后，世界与角色一致地重新计算。

实施状态：已完成初始营地、第一簇回响、营地苏醒三态；篝火、路标和工坊具有独立点击区域及可访问名称。世界状态由当前有效结算日期实时推导，角色属性与场景物件均可打开来源日期、旅志全文和成长依据。API 35 设备端测试已验证零成长日期计入营地、第三个不同日期唤醒工坊，以及修改、过期和删除后的自动回退。

### 后续 D/E

D 验证七日体验：可选的次日线索、周旅程回顾和快速记事。E 用真实 AI 取代演示识别，并完成同意、校验、重试与隐私验收。D 和 E 的顺序可随试玩反馈调整，A–C 的数据与规则约束不变；正式对外发布前必须完成 E，或明确以无 AI 的演示版发布。

### 后续角色开场

旅人登记与初始画像尚未实现。实施时按 [旅人登记与初始画像实现文档](CHARACTER_ONBOARDING_IMPLEMENTATION.md)执行；该画像不进入成长账本，不影响属性点或营地里程碑。

## 8. 暂不扩张与验证重点

本阶段不加入金币商店、装备属性、排行榜、组队战斗、GPS 轨迹、健康数据自动采集或开放式无限地图。它们会扩大开发范围，却不能先证明“真实经历塑造世界”是否成立。

首轮试玩重点观察：玩家能否在第一次结算后讲清楚自己为何成长；能否发现营地变化并找到对应旅志；第二天是否愿意自愿回来记录。若这三点不成立，优先改进记录成本、依据表达和场景反馈，再增加玩法系统。
