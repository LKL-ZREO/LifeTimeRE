# LifeTimeRE 当前阶段产品功能报告

日期：2026-11-01  
状态：产品框架建议稿，供后续功能拆解使用

## 一、结论

当前版本已经完成安卓工程、今日/角色/世界/回顾四页和像素 RPG 视觉骨架。今日页仅保存临时草稿，角色属性、营地进度和回顾内容仍是初始展示。现有方案明确了“记录 → AI 识别 → 规则结算 → 属性与世界变化”，但尚未明确玩家的长期方向、每次结算后可感知的世界反馈，以及一段旅程如何形成回顾。

目标产品闭环建议为：

> （可选）选择现实方向 → 记录生活 → 得到有依据的回顾与成长 → 看见营地变化 → 获得可选的下一步线索 → 在周回顾中看见自己的旅程。

产品定位建议为“由真实经历推动的个人冒险世界”。玩家决定自己想走的现实方向，不决定属性类别和加点数值；AI 整理经历并解释依据，固定规则负责结算，世界负责呈现长期变化。

## 二、当前已有与主要缺口

| 维度 | 当前状态 | 需要补齐的产品能力 |
| --- | --- | --- |
| 日常记录 | 今日页可输入临时草稿 | 正式保存、修改、按日期查看；以后可增加快速记录 |
| 角色成长 | 五项属性与初始立绘 | 有依据的结算反馈、等级/称号及可追溯的成长记录 |
| 游戏世界 | 一处像素营地及静态阶段展示 | 随里程碑变化的场景、明确的解锁条件和个人化细节 |
| 冒险方向 | 尚无长期目标 | 玩家选定一个现实方向，形成持续但可调整的个人旅程 |
| 行动延续 | 记录与结算后结束 | 根据当天经历提出可选的次日小行动 |
| 阶段回顾 | 空状态 | 日志时间线，以及串联行动、困难和世界变化的周回顾 |
| 信任机制 | 方案中已有规则约束 | 在界面中展示成长依据、失败状态、修订和纠错入口 |

这里的“生活轨迹”在第一版指玩家自己记录的时间线，不默认指 GPS 位置轨迹。定位采集会显著改变权限、隐私和产品体验，应单独评估。

## 三、当前适合加入的功能

### P0：首个完整循环必须具备

1. **个人冒险方向。** 玩家可选择一个现实目标或主题，如“建立运动习惯”“完成作品”“持续学习”；初次使用可以跳过，以后再设置或修改。它影响任务线索、叙事和世界细节，但不指定属性得分。
2. **正式旅志。** 玩家可以保存、修改、删除当日记录，并在回顾页按日期找回。当天多次修改属于同一段旅程，不靠重复提交刷成长。
3. **回响结算页。** 一次结算同时给出简短的事实回顾、识别出的行动、引用的原文、属性变化及未获得成长时的中性说明。保存记录和完成结算必须有不同的状态。
4. **角色成长。** 保留现有五属性：力量、耐力、学识、技巧、韧性。属性数值由结算账本推导；等级和称号可作为阶段反馈，不需要额外加点操作。
5. **营地的第一轮可见变化。** 从当前“微光营地”出发，至少设计 3 个清晰可辨的状态，例如篝火、工坊、书房逐步出现。解锁依据为累计的真实行动与固定里程碑；相同玩家行为应产生可预测的结果。
6. **成长依据与纠错。** 每项成长都能追溯到哪一天、哪段记录。玩家可以更正记录或对分类提出异议，但不直接编辑获得的点数。修订后替换旧结算，并在界面说明数值为何变化。
7. **安心的节奏。** 休息、身体不适或中断记录不扣点，也不制造“连续签到断了”的惩罚。提醒与下一步行动均可跳过。

### P1：完整循环稳定后的增强

1. **冒险线索。** 根据玩家目标和当天记录，提出 1–2 个次日可选的小行动；玩家可以接受、跳过或改写。完成与否仍由后续真实记录确认。
2. **周旅程回顾。** 汇总一周做过的事、持续投入、调整过的计划，以及营地的具体变化；避免只报属性总分。
3. **快速记下一件事。** 白天随时补一条短记录，晚间汇成当日旅志，降低长篇写作门槛。
4. **营地个性化分支。** 同样达到一个里程碑，长期偏向学识、技巧或体能的玩家可以看到不同的房间、摆设或角色对话。分支只改变表达，不让某种生活方式获得更高基础收益。
5. **旅行纪念册。** 保存重要节点的场景快照、称号和对应的真实经历，让游戏成就与现实故事相连。

### P2：有使用反馈后再评估

更多区域、NPC 支线、装备外观、深度技能树、组队、排行榜、健康平台或定位数据接入。这些功能会扩大制作量或改变隐私边界，首个营地循环尚未验证前不宜成为主线。

## 四、四个页面如何承载这套框架

| 页面 | 核心任务 | 首批新增内容 |
| --- | --- | --- |
| 今日 | 轻松记录当天真实生活 | 保存状态、当日记录、结算入口；后续加入快速记录和冒险线索 |
| 角色 | 看见“我变成了怎样的人” | 五属性变化、成长依据、等级/称号；不设手动加点 |
| 世界 | 看见行动的长期结果 | 营地阶段、下一里程碑、已解锁的场景变化和个人目标 |
| 回顾 | 找回经历并理解趋势 | 日期时间线、记录编辑、结算详情；后续加入周旅程回顾 |

可在结算完成时打开一个短暂的“回响揭示”视图：先展示当日依据与属性，再展示世界发生的具体变化。这个瞬间是首版最关键的 RPG 体验，应比泛用装备或金币系统先完成。

## 五、推荐的产品里程碑

| 里程碑 | 用户能完成什么 | 验收重点 |
| --- | --- | --- |
| A. 可留下旅程 | 可选方向，保存和找回每日记录 | 重启后仍在；当天修改正确；删除可控 |
| B. 第一次成长 | 记录后得到回顾、依据、属性变化 | 看得懂为何成长；重复提交不重复加分 |
| C. 营地回应 | 成长推动营地发生第一处明显变化 | 场景变化与规则一致；玩家能发现变化 |
| D. 七日旅程 | 收到可选线索，查看一周的经历与世界变化 | 不记录或休息不会受罚；回顾基于真实记录 |
| E. 真实 AI | 用后端 AI 替换模拟识别 | 明确同意、结构校验、失败可重试、旧响应不覆盖新记录 |

底层实现仍可按 Room、成长规则、AI 接口推进，但每个里程碑都应交付一段玩家能亲自体验的过程。A 到 C 是第一版核心验证范围；D 负责验证持续使用的理由。

## 六、先确定的产品规则

- **成长依据：** AI 只识别行动类别、有限等级和证据；固定规则决定数值。保留目前单属性每天最多 3 点、每日总计最多 8 点作为待试玩的初始参数。
- **世界变化：** 第一版只制作营地，多阶段变化必须有明显画面差异；解锁条件保持可解释。长期个人化分支放到 P1。
- **目标与行动：** 玩家可以选现实方向和接受行动建议，但无法通过声明“我要获得力量”来控制分类或得分。
- **休息与挫折：** 不奖励受苦本身，不因休息扣分。面对困难后的调整可以被描述为经历，但数值结算应谨慎。
- **叙事真实性：** AI 可以润色回顾和世界文字，不能编造玩家完成过的事。修改或删除原记录后，对应回顾及成长必须同步更新。
- **隐私边界：** 首版以手工输入为主；启用远端 AI 前说明传输内容并取得同意，提供删除记录和派生内容的入口。

## 七、优先验证的问题

1. 玩家是否能在第一次结算后理解属性变化，并感到营地的变化与自己有关？
2. 玩家是否愿意在没有额外惩罚或连续签到压力的情况下，第二天再次记录？
3. 一周后，玩家更在意属性数字、营地变化，还是由真实经历串成的回顾？这将决定后续美术与剧情投入方向。

首轮验证宜观察完成首次记录、查看结算依据、发现营地变化以及七日内自愿回访的情况。不要只用累计点数判断体验是否成立。

## 八、参考与判断边界

- [Habitica Features](https://habitica.com/static/features)：任务、经验、装备与组队任务已有成熟做法。
- [Finch Self-Care Areas](https://help.finchcare.com/hc/en-us/articles/37780731973133-Self-Care-Areas)：个人领域、目标和每周里程碑的同类参照。
- [LifeUp Introduction](https://wiki.lifeupapp.fun/)：属性、技能、成就与奖励商店的同类参照。
- [Chopra 等，Engagements with Generative AI and Personal Health Informatics](https://dl.acm.org/doi/10.1145/3749503)：对 AI 辅助追踪、反思、计划和行动的探索性研究。

上述产品说明了同类功能已经存在；“个人经历塑造世界”是本项目的产品判断，尚未经过用户测试验证。
